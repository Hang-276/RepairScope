# RepairScope-Evo：持续改进修复知识的分阶段研究提案

**英文工作标题：** Self-Improving Repair Knowledge through Joint Counterfactual Execution  
**版本：** Phased Proposal v1.0 · 2026-10-17  
**研究目标：** 从执行经验中发现、验证、修订条件化修复知识，使 Agent 恢复失败目标时更少破坏已有进度，并将知识迁移到后续任务。  
**资源约束：** 单张 RTX 4090 24GB；首版冻结模型参数；优先复用已有 AppWorld 工程与现成任务；不人工构造大型任务集。  
**本文地位：** 研究与执行计划，不是已完成的实验报告。所有新增数量、阈值和预算都是本版建议，须在运行前落入配置；不代表新方法已经通过验证。

> **本版最终决策：保留“操作变化 × 条件变化”的联合反事实执行，只演化修复知识 `K_repair`；实验提议策略先固定，不将 `K_probe` 元级自进化作为主论文的必要条件。先验证真实机制，再实现持续学习，再投入正式评测。**

## 1. 一页执行摘要

### 1.1 我们究竟要做什么

原 RepairScope 学习“给定候选会恢复或破坏哪些目标”，主要用于候选排序。本版改为学习：

> **某种补偿操作在什么条件下真正有用，何时多余，何时会产生副作用；新经验出现后，如何修正这条知识，而不是不断堆积经验文本。**

模型权重保持不变，持久化的修复规则、适用条件和证据会改变后续修复行为。核心实验要证明：这种知识演化比普通记忆积累、相同反馈下的知识整理和单纯增加搜索预算更有用。

主线是**知识级持续自改进**。只有以后单独证明“演化的实验知识能够改善未来学习效率”，才增加更强的元级 RSI 主张；当前不为此开发第二套系统。

### 1.2 数据与实现的取舍

| 项目 | 本版决定 |
|---|---|
| 主环境 | 已部署的 AppWorld 0.2.0，固定原有源码提交，不追随最新版升级 |
| 主数据 | 官方 train 学习、dev 开发、两个官方 test 最终冻结评测 |
| 第一优先级 | 复用现有 train 轨迹、目标抽取、真实候选和前缀重放 |
| 少量补样 | 必要时调用官方 **train 场景生成器**，不手写新场景，不重建 Base DB |
| 反事实来源 | 在隔离训练副本中，经合法 API 改变条件并执行固定程序；全部单独标记 |
| 第二环境 | 仅在主环境覆盖不足或需要独立验证时，审计已有 τ-bench Retail；不默认同时开发 |
| 模型 | 现有冻结 Qwen3-8B-AWQ；Actor、知识归纳和修订顺序复用同一服务 |

| 旧 GATE 2 | 归档为旧问题的未完成验证，不继续为 50/50 四态标签数量采数 |

## 3. 研究问题、假设与创新边界

### 3.1 研究问题

在外部状态会被操作持久修改的工具环境中，Agent 经常把一次成功经验概括得过宽或过窄。我们研究：

> **有限的“修复程序变化 × 局部条件变化”执行对照，能否帮助系统学到可修订的条件—补偿关系，并减少未来任务中的不足修复、过度修复和目标破坏？**

这里的修复从**当前真实状态**出发，不是把历史错误假装撤销后重新开始。

### 3.2 三项主假设

| 假设 | 正面证据 | 能够否定该解释的结果 |
|---|---|---|
| H1：存在条件性修复结构 | 同一补偿在条件 A 有益、条件 B 多余或有害；其他关键因素受控 | 只发现总是有效或总是无效的固定脚本，找不到条件性差异 |
| H2：联合对照改进知识 | 同样反馈下，条件知识在留出状态中优于普通经验整理 | 给普通记忆相同执行证据后差距消失 |
| H3：知识进化能迁移 | 后期冻结知识优于早期知识，且在不参与更新的任务中成立 | 仅学习期重复任务变好；关闭测试分支后没有迁移收益 |

强元级 RSI 不是主假设。论文主张先限定为 **execution-grounded continual self-improvement of repair knowledge**。

### 3.3 已有研究与本版差异

ACE 将经验持续积累、反思与整理为可演化上下文；ReasoningBank 将成功与失败经验转为可复用记忆，并研究记忆与额外交互的相互促进。它们直接构成“仅增加持续记忆”这一解释的强对照。[R1][R2]

SkillCommit 通过行为验证控制技能适用范围扩展；Skill-V 用可检验契约与结果差异维护技能；SkillEvoReg 已经具有定向反例和新旧技能的配对验证。因此，规则、回放、契约和四格实验本身都不能当作独有贡献。[R3][R4][R5]

**本版的创新候选是一个整体：** 联合执行识别“何时需要何种补偿” → 把这种条件关系变成影响真实修复生成的持久知识 → 通过后续反例修订 → 在相同资源下获得迁移收益。

这只是待验证的技术差异，不是已经完成的新颖性证明。主实验必须包含相近知识维护机制，不用一个弱 ReAct 对照代替相关工作比较。

## 4. 方法设计与知识更新闭环

### 4.1 输入、目标与可见性

- `x`：当前合法可见的任务指令、交互历史、API 文档及查询返回。
- `s`：环境真实状态；仅环境与离线评测器可完整访问，不直接注入模型。
- `G_fix`：本次修复承诺恢复的目标集合。
- `G_keep`：在执行前已经满足、且应保留的任务目标或明确保护要求。
- `r0`：基础修复；`r1`：在明确位置加入补偿片段 `δ` 后的修复。**不默认 δ 总是追加在末尾，执行顺序也是机制的一部分。**
- `K_t`：任务 t 开始前的修复知识。

模型在线只能根据 `x` 推断目标状态。真实 `G_fix/G_keep` 标签用于离线学习与机制评估；不得通过隐藏 checker 决定在线何时干预、选择哪个修复。

保留的是语义目标，不是“所有原字段值都不能变”。第一版只评估修复代码块结束时的恢复与保留，不能据此宣称全过程安全。

### 4.2 最小知识结构

```json
{
  "rule_id": "stable_rule_identifier",
  "version": 1,
  "intent": "parameterized repair intent",
  "applicability": {
    "observable_conditions": [],
    "required_queries": [],
    "unknown_policy": "do_not_treat_as_verified"
  },
  "repair": {
    "base_template": "parameterized program or grounded procedure",
    "conditional_compensation": [],
    "read_scope": [],
    "write_scope": []
  },
  "goal_effects": {
    "recovery_claims": [],
    "preservation_claims": []
  },
  "evidence_ids": [],
  "counterexample_ids": [],
  "status": "provisional"
}
```

这是拟新增的数据接口，不是已经存在的代码。具体训练任务的 ID、答案和实体字面值留在审计档案；可部署知识只保存参数化机制与允许使用的公开 API 语义。条件必须能由实际观察验证；未知条件不能被默认判真。

知识状态为 `provisional / validated / restricted / deprecated`。弃用保留版本和反例，不物理删除证据。`validated` 只表示通过规定证据，不代表普遍正确。

### 4.3 联合反事实实验

从一个自然学习事件确定补偿片段 δ 和竞争解释，比较：

| | 基础修复 r0 | 带补偿修复 r1 |
|---|---|---|
| 条件 c0 的状态 s0 | 固定代码执行 | 固定代码执行 |
| 条件 c1 的状态 s1 | 固定代码执行 | 固定代码执行 |

对保护目标 g，记录结束状态 `Y_g(s,r)`，可计算样本内交互：

```text
I_g = [Y_g(s1,r1) - Y_g(s1,r0)]
    - [Y_g(s0,r1) - Y_g(s0,r0)]
```

不把 `I_g != 0` 单独当作普遍因果结论。还须同时检查同一恢复承诺、保护目标、实际写入、程序合法性、条件变更及可见观察。

**向内对照：** 只做依赖合法的操作删除、替换或顺序调整。变量未定义、语法损坏、非法参数和截断不算语义必要性证据。第一版不做任意程序全局最小化。

**向外对照：** 优先用公开 API 在隔离副本建立不同条件；记录全部附带改变。不能只改 prompt、随机改隐藏 DB、假定两个不同任务就是严格配对。某条件只能伴随多项改变时，结论限定为该变化组合，不能归因于单一因素。

**对照可比性：** s0、s1 应保留相同任务语义、待恢复目标及执行前保护目标的满足值。改变“所有符合某条件的对象”的成员集合，可能已经改变任务答案，此类干预必须拒绝或单列为另一任务实例，不能作为纯背景对照。

**checker 有效性：** 原生 evaluator 若引用初始状态或检查全局无副作用，不一定适用于条件已改变的影子世界。影子机制标签使用经过审计、在两种状态上仍有同一语义的目标谓词；不能把干预本身引起的差分算成修复损害。无法保证适用则记 `unknown`，不得修改官方 evaluator 使之通过。原生任务的最终评分始终使用原 evaluator。

### 4.4 固定的实验选择与知识修订

每个学习事件至多保留三个可检验解释，例如“δ 总有益”“只在 c 下有益”“δ 无益”。固定规则优先选能够区分解释且成本低的合法执行，不训练另一个实验策略。

更新操作仅包含：新增、条件收窄、条件扩展、补偿增删、局部分支拆分、弃用。第一版不做复杂的跨库聚类、层级技能发现或自动合并。

提交更新需要：

1. 新主张有执行证据；自动提炼的条件不得来自隐藏参考解。
2. 至少修复当前已观察到的一项知识错误，或提供此前缺失的有证据能力。
3. 相关旧证据未发现新增已知损害；固定程序验证与重新生成的行为验证分开记录。
4. 用户目标、checker、预算、数据划分和历史反例没有被更新器修改。

单次新模型输出较好不构成稳定改进。预算不足时保留候选版本，不强制提交。所有“未更新”也计入学习效率分母。

### 4.5 主循环：先计分，后学习

```text
K = empty_or_protocol_frozen_initial_knowledge

for task in training_stream:
    result = run_real_task(task, K, fixed_actor, normal_budget)
    save_original_result(result)                  # 不可被后续学习覆盖

    event = select_event_from_this_and_past_training_experience(result)
    if event is None:
        continue

    hypotheses = propose_at_most_three_explanations(event, K)
    evidence = execute_bounded_joint_probes(hypotheses, training_clones_only)
    proposal = revise_repair_knowledge(K, evidence)

    if fixed_validation_accepts(proposal, relevant_past_evidence):
        K = commit_version(proposal)
    else:
        record_unresolved_event()

    persist_snapshot_and_budget(K)
```

同一任务内 `K_t` 固定；在线观察可以变化，但完成任务前不利用隐藏分支选出成功修复。任务 t 的影子实验只能影响后续任务或以后独立的知识评测，不替换任务 t 的真实成绩。

### 4.6 在线修复如何使用知识

保留当前出错、每 5 个执行块、完成宣告前的固定触发。主 Actor 提出 original；修复候选的数量与预算先沿用既有框架。知识只在修复阶段使用，不暗中改写基础 Actor 的所有动作。

CPU 上固定检索最多 3 条相关知识；先做条件检查，再根据相关证据、**完整任务要求**和读写范围生成修复。知识应用失败或条件未知时回退原有通用修复流程。所有同类对照共用检索预算、候选数和选择器；第一版复用冻结 direct 选择，不新训练排序模型。

允许两次顺序调用同一模型：条件/相关证据选择 → 边界条件化修复生成。第二次真正重组上下文，不把范围说明作为无效装饰；但不能删除原任务要求以伪造局部性。所有辅助调用与查询均计入实际成本。

| 官方划分 | 任务/scenario | 本版用途 |

| train | 90 / 30 | 自然轨迹、知识学习、影子执行、训练侧按场景留出 |
| dev | 57 / 19 | 冻结快照评估、开发决策；禁止反向写入知识 |
| test_normal | 168 / 56 | 最终冻结原生评测 |
| test_challenge | 417 / 139 | 最终冻结挑战评测 |

规模为本项目固定 0.2.0 数据的已验收 manifest，不混用历史论文或未来仓库规模。[P1] 官方提供原生环境、任务、数据库状态评估及 train/dev 的生成与验证资源；本版以它们为基础，而不是创建新 Benchmark。[D1][D2]

### 5.2 一次性定义 Evo 资格，避免反复改口径

旧 R3 只允许“至少两个目标，且所有目标都是 state_write”。本版建议在 P0、观察新方法结果之前固定新的 `EvoEligibility-v1`：

**任务层：** 从原始指令和公开任务要求中，可以抽出至少两个独立、持久、可操作的状态目标或明确保留约束；允许同时存在最终回答等其他目标，但其他要求必须完整保留。无证据的隐含保护目标不能由研究者凭空添加。

**学习事件层：** 至少存在一个待恢复目标与一个执行前已满足的保护目标，且它们能够可靠判断；这种真值只用于离线样本是否可研究，不能泄漏给在线触发器。

**知识应用层：** 仅依据可见条件和固定抽取结果启用，不依据隐藏 checker 判断任务是否适合。

这是新协议，不回写旧 R3 结果；所有正式表同时报告新资格覆盖和旧 R3 子组。按 D1，R2 口径 train 有 19 个、dev 有 5 个任务，而 R3 分别为 14 和 5；这只说明潜在多出 **5 个 train 候选**，不保证这些任务可标注，也不保证增加 scenario。[P1]

抽取器首先复用 D1 冻结结果，不为了提高覆盖重新提示直到满意。需要修正抽取缺陷时只能统一版本变更并重做受影响协议，不挑任务手工补目标。

### 5.3 区分“修复”与一般任务推进

为每个学习事件保留来源标签：

| 来源 | 定义 | 可支持的结论 |
|---|---|---|
| `natural_regression` | 目标曾满足，后因实际操作退化 | 真实进度退化与恢复 |
| `natural_failure` | 可见错误或部分写入导致计划偏离 | 错误后的恢复；是否目标退化另报 |
| `natural_incomplete` | 目标尚未完成，没有已确认退化 | 增量完成或预防干扰，不能冒充损坏恢复 |
| `cf_intervention` | 训练副本中的合法条件干预 | 机制对照，不是原生自然失败频率 |
| `official_generator` | 官方 train 生成器的新实例 | 同机制的新增实例，不是新增场景 |
| `synthetic_fixture` | 人工小夹具 | 仅单元测试，不进入研究结果 |

P1 的保护损害与条件性补偿证据不能全部由人工注入故障制造。真实自然任务中的失败/未完成状态和候选执行应是起点；干预用于辨别条件，不用于把主任务改得“正好适合方法”。

### 5.4 数据扩展按成本顺序，只启用必要层

**L0：现有文件与轨迹。** 优先使用完整的 train 执行记录、候选和已抽取目标。缓存有一致 hash 的固定代码重放，不重新调用 LLM 重建相同轨迹。

**L1：原生 train 中尚未执行的合格任务。** 以固定 scenario 轮转顺序补采。主表保留全部任务分母；未合格任务按原系统执行，不将其从官方结果删除。

**L2：有限官方场景再实例化。** 只有已确认机制存在、但缺少迁移实例时启用。固定提交下的官方指南确实提供 `TaskGenerator` 实例化及参考解验证入口；它不是我们发明的新数据生成器。[D2]

具体约束：

- 仅从当前学习分区中的 **train generator 白名单**产生；不得调用 `all`，不得使用 dev/test 或训练侧留出场景的生成器。
- 不改生成器逻辑、不改目标、不手写参考解、不重建 Base DB。生成器所需额外依赖进入独立环境，不破坏已有执行环境。
- 首轮建议每个已选 train generator 最多新增 10 个实例，合计最多 100 个；这是上限而不是采满目标。固定随机性并记录生成失败，不能不断采到期望结果。
- 在独立数据根目录与命名空间保存，不能覆盖 `_1/_2/_3` 原生任务；使用本地接口说明确认参数，不能猜测 CLI。
- 官方 solution 只在验证器进程执行以验证新实例；不读取为修复示范、不注入 Actor 或知识归纳器。
- 生成器出新实例并不保证产生我们想要的条件变化；条件覆盖要实测，没有变化则停止该生成器扩样。
- 自然原生数据与新增实例分别报告。基于此学习所得结果标明 `train + official-generated augmentation`。

**L3：仅按需审计一个已有第二环境。** 只有 AppWorld 的机制覆盖成为实质障碍，或 P3 已成功而需要独立外部验证时启用。默认先审计 τ-bench Retail；不启动多环境全面开发。

### 5.5 第二环境的选择与限制

| 候选 | 可复用内容 | 本版处理与风险 |
|---|---|---|
| **τ-bench / τ²-bench 系列 Retail** | 官方政策、工具、任务、环境与评分；当前仓库提供 Gym 研究接口及 solo 模式说明，具体学习/评测划分接入前核验 | 唯一优先备选。先固定 commit、任务划分与模式；不可撤销操作、对话模拟方差以及目标可分解性必须先审计。[D3][D4] |
| **ToolSandbox** | 状态化工具、快照、工具依赖、里程碑评估 | 仅保留候选记录。里程碑达成不等于持久目标仍成立；部分场景需要外部搜索服务和用户模拟器，不默认迁移。[D5] |

**版本提示：** 2026-10-17 核验时，名为 `tau2-bench` 的官方仓库 main 已描述 τ³-bench，并记录任务修复和接口变化。不能直接拉 main 却把结果称为原论文 τ²-bench 复现；必须保存具体版本、模式与对应评分配置。主线仍是已固定的 AppWorld，不因此升级本项目依赖。[D3]

接入前必须核验该版本提供的合法学习/评测划分及任务家族重叠。不能先在完整 `base` 任务集学习，再在同一 `base` 上宣称独立评测；确需研究侧分组划分时应明确标为自定义划分，而非官方榜单分数。

若使用官方 solo 模式节约用户模拟成本，结果必须标为该模式，不能与标准对话模式分数等同。若标准模式需要用户模型，模型版本和计算也计入预算；不能省掉模拟器后继续称原生复现。[D4]

第二环境先做**至多 5 个已有任务的兼容性审计**：是否有合法重放、可判定持久保护目标、可执行补偿、可观察条件。需要大量重写任务或评分器则不接入。第二环境中的知识需要从其自身合法训练数据重新学习；不要求同一 API 规则跨环境零样本迁移。

### 5.6 “不自建大型数据集”的可验收定义

本项目**不新增**人工编写的主实验任务、参考修复答案或每场景专用正确规则。允许的人工工作是通用接口实现、已有目标/checker 映射审计、数据边界检查和对无效样本的标记。

每个学习事件记录 `human_task_edits / human_rule_edits / human_intervention_edits / audit_minutes`。本版主机制实验要求前三项为 0；人工审计不能改成向模型泄漏正确条件。人为修复过的个案只进入诊断档案。

因此，计划是 **现成任务 + 自动执行经验 + 少量按需干预**，而不是声称完全没有数据工作。若每个机制都要研究者写专用干预或修复程序，项目不满足用户约束，应停止扩张。

## 6. 分阶段目标、预算与验收

### 6.1 统一推进规则

每阶段结束只交付一次结构化报告：`目标 → 实际输入 → 完成工作 → 证据 → 成本 → 未解决问题 → 继续/停止建议`。

下述 Gate 是工程与投入决策条件，不是统计显著性或录用标准。不得为了达标事后改变分母、手写机制或不断提高采样预算。新增方法效果出现前冻结 P0/P1 规则；P3 前再一次性冻结正式比较配置。

### P0：资产盘点与协议固定

**目标：** 从已经跑通的系统出发，不重新做环境工程。

**工作内容：**

1. 读取服务器实际 Git HEAD、dirty diff、模型锁文件、环境 manifest 和已有 receipts；保留 F1 未提交工作。需要新分支时，从当前含 C2/C5 的实际工作状态派生，不直接从旧 main 开始。
2. 核对目标冻结文件；不存在则从已有 D1 输出生成并记录 hash，复用原抽取结果。
3. 固定 `EvoEligibility-v1`、P1 任务次序、所有预算、只读 dev/test 规则及旧协议迁移记录。
4. 建立 train 轨迹索引与来源标记；确认可复用的前缀包含 Python 执行上下文和错误产生的部分写入。
5. 只对修改的接口做小测试。旧环境验收仍有效时，不重跑 12 任务 E3、不重测一轮服务确定性、不重下模型。

**交付物：**

```text
runs/evo_v1/assets.json
runs/evo_v1/protocol.yaml
runs/evo_v1/protocol_migration.md
runs/evo_v1/data_manifest.json
runs/evo_v1/goals.lock.json
runs/evo_v1/P0_report.md
```

**通过条件：** 版本和数据身份确定；目标可冻结；学习分支无法访问 dev/test 学习数据；至少一个已存在前缀能够按既有验证规则重放。若相关组件未改且有可信 receipt，可引用已有证据，不重复运行。

**资源边界：** 不启动新的全量 capture、训练或测试。P0 的重点是读已有产物，不用新性能数字作为通过条件。

### P1：一次性最小可行性验证

**目标：** 在实现完整自进化框架前，判断自然环境中是否存在可自动学习的条件性修复机制。

**首批样本：** 3–5 个原生 train 任务、10–15 个不同状态，按预先固定的 scenario 轮转顺序取样；优先复用现有主协议轨迹。新候选与现有候选都计入分母，不根据是否有利于 ours 决定哪些状态进入报告。

**资源上限：**

| 项目 | 首批上限 | 说明 |
|---|---:|---|
| 不同自然状态 | 15 | 同一语义状态的重复 checkpoint 不重复计数 |
| 每状态初始候选 | 4 | 原框架候选池；不无限采样直到成功 |
| 每学习事件的新影子分支 | 12 | 含候选核验、操作/条件对照和更新所需回放；缓存命中单列 |
| 首批影子分支总数 | 180 | 非必须用满；超限事件记 unresolved |
| 留出行为检查 | 最多 3 个案例，每案例最多 3 次新旧知识配对重复 | 最多 18 次行为评估，单列成本，不伪装成免费缓存 |
| 预设覆盖扩展 | 最多再增加 15 个状态、180 个影子分支 | 只允许一次，从尚未检查的原生 train 合格任务中选择；不加新机制模块 |

首批没有足够成功见证时，可在同一个 P1 中使用上述固定扩展。补采不能超过已有 Evo 资格 train 任务清单的一轮；不能一轮失败后不断换随机种子。扩展完成仍无证据时给出停止结论，而不是再创造 Gate 2-Lite-v3。

**P1 内部顺序：**

**A. 成功修复见证。** 固定当前状态和候选，离线执行并审计目标真值。至少获得 3 个真实有效修复，覆盖至少 2 个 scenario。每个见证恢复其预先声明的目标并保留可可靠判断的已有目标。只完成无关读取或继续普通任务推进，不算条件化恢复证据。

**B. 条件—补偿关系。** 对候选中的一个语义补偿片段，自动提出合法程序变体和可观察条件变体。至少发现 2 类不同机制；“同一个模板换文件名”不是第二类。每类都提供固定程序的受控执行、完整目标向量和状态差分。至少能看到补偿作用随条件变化，而不是单纯说明某条程序成功。

**C. 自动知识演化。** 系统自行归纳 `K0 → K1`，在新经验暴露边界问题后形成 `K1 → K2`。不允许研究者填入正确条件。至少一次实质修订改变后续生成行为，并在未参与这次归纳/修订的任务或状态中改善恢复或减少不必要损害；相关旧情形没有发现新退化。最多 3 次配对行为运行用于排除明显偶然性，报告所有结果；这不是统计结论。

**防止循环证明：** 导致修订的反例可以进入学习池，但不能同时成为该修订的“独立迁移证据”。迁移状态在首次评估前不得参与此次规则生成、实验选择或回归门控；评估后若再用于学习，必须移动分区并记录时间。

**必须交付的证据：**

```text
P1_report.md
witnesses.jsonl                 # 包含成功、失败、unknown；不能只保留正例
joint_probes.jsonl              # 四格执行，程序/状态/条件 hash 与有效性检查
knowledge_versions.jsonl       # K0/K1/K2 差分、自动生成内容和证据
transfer_cases.jsonl           # 未参与本次修订的案例与全部重复结果
coverage_and_cost.json          # task/scenario/mechanism/人工编辑/成本分布
```

**继续条件：** A、B、C 都有实际证据，且没有依靠逐任务人工修复；此时才进入 P2。若 A/B 通过但 C 不通过，只分析知识应用失败的已有轨迹，不预设再增加一个新架构。

**停止/切换条件：** A 失败首先区分 Actor/候选质量与环境；B 失败重点判定合法干预或结构不足；大量人工补干预才能完成则不满足本项目约束。最多按第 5.5 节审计一个已有第二环境，不启动大型自建任务工程。

### P2：实现最小持续学习系统

**目标：** 把 P1 的证据链变成可复现的连续任务学习器，而不是扩大方法复杂度。

**只实现以下能力：** 版本化知识、固定检索与条件检查、有预算的联合执行、局部修订与证据验证、串行任务流、冻结快照。`K_probe`、LoRA 与 RL 都不实现。

**默认设置：**

- 知识 `K0` 为空；旧 P1 提炼的规则只用于开发案例，不直接充作声称“自主冷启动”的主实验初始知识。
- 每个完整训练任务最多 2 个学习事件，每事件最多 12 个新影子分支、6 次学习侧模型调用、合计 8000 个学习侧输出 token。此限制包含提议、修订与更新验证中的生成；不包括另行记账的独立留出评估。先固定一个任务顺序；没有事件的任务也保留记录。
- 官方 train 单次遍历，不默认通过反复训练同一批任务制造更长学习曲线。
- 活跃规则上限建议 32 条，检索最多 3 条、注入文本合计最多 2048 token；溢出规则保留档案，不让知识无限膨胀。
- 规则检索、固定预算和验证器在该阶段冻结，不能边看曲线边增配。

**数据补样触发：** 只有“存在明确机制，但缺少可复用的新实例”时，才启用 L2 官方 train 场景再实例化。先在 1–2 个已许可 generator 上做接口验证；是否继续由可用性和覆盖决定，不以 ours 得分决定。原生数据和新增实例保留两条独立设置。

**通过条件：** 至少完成一个从空知识开始的合法训练流；每次更新有证据和版本；同一任务成绩不被重跑覆盖；知识快照可重新载入；在线 actor 不接收 hidden checker；没有把 dev/test 经验写进 K。该阶段不要求方法已经显著优于 baseline。

**交付物：** 可运行入口、最小单元测试、一个完整 stream receipt、`K_empty / K_mid / K_final` 快照、各来源成本和泄漏审计。

### P3：机制、持续改进与迁移验证

**目标：** 决定它是否值得投入正式完整 test，而非仅证明软件能循环。

**先固定数据分组：** 所有同 scenario、同 generator 的任务及其派生状态绑定。优先使用 train 内按 scenario 的分组留出；预先用 instruction-level 资格分层，尽量让留出组包含可研究事件，不能根据方法成绩决定留出谁。

首轮只跑一个固定分组，不立刻展开“全部方法 × 5-fold × 3 seeds”。若进入完整机制分析，主要方法与最强反馈匹配对照再做分组交叉验证；小样本 fold 的 support 必须一起报告。官方 dev 单独用于开发，只有 2 个旧 R3 合格 scenario 时不能把其窄置信区间视为可靠泛化证据。[P1]

**三项核心实验：**

1. **证据相同的学习比较：** 各学习器按相同时间顺序获得同一份已生成的 train 证据包，比较普通经验整理与条件化知识更新。包中不得标出人工总结的“正确机制”；只提供各自可用的执行结果。
2. **自主学习闭环比较：** 各方法在相同任务流、actor 和预算下自行采经验及更新。由于轨迹会分化，不声称它们看到完全相同的状态。比较学习总成本和冻结后的收益。
3. **时间快照迁移：** 保存 `K0 / K25% / K50% / K100%`，在不参与更新的固定开发/留出集合评估。评估结果不回流知识，不依据最好快照挑选“最后模型”；最终知识默认使用固定流结束时版本。

**行为指标：** 条件化修复是否改变真实生成；同目标恢复下是否更少破坏已有目标；规则更新是否减少同类错误；冻结知识且关闭影子分支后是否仍有收益。

**通过/投入判定：** 收益不能仅由 extra feedback、更多 token 或重复任务解释；双向联合相对关键消融应出现可重复的机制证据；至少有未参与更新的状态/场景支持迁移，且成本在预先预算内。P3 不强制要求仅有少数 scenario 的 dev 达到 p<0.05；若证据不足，保留不确定性，不把小样本偶然优势作为投入依据。

**交付物：** 预注册比较配置、分组 manifest、时间快照曲线、证据匹配结果、关键消融、scenario 分项统计、冻结测试建议。

### P4：冻结主评测与论文证据

**目标：** 在完整原生任务中检验已学知识是否有实际价值。

**执行协议：**

- 方法、提示、资格、检索、checker 审计映射、预算、任务顺序与评价脚本全部冻结。
- 各最终学习器从规定的 `K0` 重新开始，用官方 train 学习；若使用官方生成增强，设置名称必须明确，并保留原生 train-only 比较。
- 预先固定 3 个学习任务顺序/随机配置（建议 100/101/102），各生成独立知识库；不得从多个流中只选最好一个。
- 每个最终知识库在 `test_normal=168` 与 `test_challenge=417` 上完整评测，测试期间不更新 K、不运行带隐藏评分的影子搜索。
- 报告全量 TGC/SGC、资格覆盖、实际干预、成本与失败分母。未合格、超限、解析失败等都留在官方分母。
- 测试只获取允许的聚合结果。案例分析使用训练侧留出或 dev，不从 test 的个案错误反向改方法。

3 个学习流快照各做一次最终评测，会同时包含知识学习与部署解码方差，不能把这两项方差分别估计为已知；需要分离它们时，先在 dev 固定同一知识重复部署，并单列额外成本。

如果预算不能完成上述主评测，应在 test 开始前降低**所有方法一致的**重复规模并说明限制；不能先看结果再挑任务或仅重跑 ours。也不能把只完成 test_normal 的结果描述成完成全部 AppWorld 评测。

**第二环境：** 不是自动解锁事项。只有独立验证确有必要且已有数据通过兼容性审计时，复用同一算法，在该环境的合法训练划分重新学习知识；固定并单列该环境的原生评分与模式。没有必要为凑两个 benchmark 改写任务。

**最终交付：** 主结果与不确定性、数据来源与人工成本、固定 commit/配置/知识版本、受许可约束的复现脚本，以及准确限定的论文主张。

### P5：可选的元级 RSI，不进入主线关键路径

只有 P4 主线已有充分证据，且有足够不同的机制学习事件时，再考虑持久化和演化实验提议知识 `K_probe`。

隔离测试必须固定相同 `K_repair`、Actor、任务与预算，仅更换初始/演化的 `K_probe`，比较未来学习后冻结迁移收益。只提高合法实验比例或反例数量不足以证明“越来越会改进自己”。不通过则不增加元级 RSI 主张，P0–P4 的贡献不因此被重新定义为失败。

<a id="evaluation"></a>
## 7. 对照、消融与统计协议

### 7.1 先做少量强对照，不复现所有相关论文

| ID | 对照 | 控制什么 | 执行阶段 |
|---|---|---|---|
| B0 | 原生适配 ReAct | 基础执行能力与整体成本 | P3/P4 |
| B1 | 相同修复脚手架，无持久知识 | 单纯候选生成/修复的收益 | P3/P4 |
| B2 | ACE 风格持续经验整理 | 记忆积累而非机制发现 | P3/P4 |
| B3 | 相同联合执行证据的普通知识整理 | ours 是否仅靠额外标签或更好的数据 | P3 核心机制实验；无需重复所有全量测试 |
| B4 | 有条件契约、适用性检查与历史回放的知识维护 | 是否仅因规则结构和回归验证 | P3/P4 |
| Ours | 条件—操作联合辨别 + 持久化修订 | 核心研究贡献 | P3/P4 |

B2 优先依照 ACE 的生成、反思、整理机制接入；ReasoningBank 是阅读与可替代实现参考，不默认再实现第七套方法。[R1][R2]

B4 以 Skill-V 的契约维护思想实现明确标注的 **adapted baseline**，并与 SkillCommit 的范围验证、SkillEvoReg 的配对反例机制做对齐检查。若原论文包含 RL、其他环境或其他更新语义，不能把冻结 Actor 的移植版称为原论文完整复现，也不能搬其原始数字作本地比较。[R3][R4][R5]

**最接近的对照不可省略：** P3 应包含 SkillEvoReg 式“现有知识/新知识 × 原实例/合法变体”的更新退化验证。可以作为 B4 的预先固定强配置或一项局部机制实验，不必为其另建完整系统。必须和 ours 的“固定基础/补偿程序 × 条件”的发现作用区分，不能只声称四格设计新颖。

“相同影子实验但不保存知识”在严格禁止当前任务获益时，其后续部署可能与 B1 完全相同。它可作为重置记忆诊断，但不要故意运行一遍冗余全量 test，并将确定相同的行为包装成强 baseline。

### 7.2 两种公平性比较都需要

**证据匹配：** 给 B3/B4 和 ours 同一按时间揭示的执行证据，不给 ours 独有的人工机制标签。该比较检验表示与更新算法。

**资源匹配：** 自主闭环使用同一 Actor、资格与触发规则、候选数、累计模型输出预算、环境分支上限与知识注入上限。各方法自行采集经验，实际开销全部报告，不用机械 padding 伪造耗时相等。

没有持久记忆的 B0/B1 不必浪费同等离线学习计算；应比较学习成本 + 部署成本及效果的取舍。参数训练和知识学习都算适应成本，`training-free` 只表示不反向传播。

### 7.3 关键消融

**必须：** 去掉操作变化、去掉条件变化、两个方向都有但不联合归纳、冻结知识不修订。

优先在固定机制池与留出状态上执行，不把全部消融都铺到 585 个 test 任务。只有与主论点直接相关且预算允许的消融才做完整闭环。

数据和计算比较同时保存：仅某个消融看到更少信息时，它不能单独证明结构设计优越。联合数据量相同、归纳方式不同的比较尤其重要。

### 7.4 指标与分母

| 层级 | 指标 | 必须一起报告 |
|---|---|---|
| 原生任务 | 官方 TGC、SGC | 完整任务分母、模式、版本、超限与失败 |
| 局部修复 | 指定 `G_fix` 完成且 `G_keep` 无破坏的比例 | 有效/unknown 数、原状态 support、代码块成本 |
| 进度保护 | 已满足目标退化次数/比例 | 恢复收益，避免“什么都不做”伪优势 |
| 机制 | 合法条件对照率、补偿的条件性作用、留出规则有效率 | 不同 scenario、关系类型与拒绝原因 |
| 持续学习 | 固定集上的快照表现、重复错误、更新新增退化 | 任务顺序、知识大小、累计学习成本 |
| 人工负担 | 通用适配/审计时间，逐任务人工改动数 | 主结果中是否出现人工修复过的样本 |

SGC 是 **Scenario Goal Completion**，不是子目标完成率。局部四态标签是辅助机制指标，不替代全任务结果。[P3]

恢复成功的分母预先固定：如果实验声称恢复整个 `G_fix`，不能在执行后将未完成目标从该集合删掉。对无法判定的目标报告 `unknown` 与覆盖；不能当成 00，也不能用删样本提高成功率。

### 7.5 统计与防泄漏

- 同一个 scenario/generator 的任务、所有前缀和干预变体属于同一组；派生实例不增加独立场景数。
- 原生 task ID 不跨分区，具体实体答案不跨任务进入可部署记忆。
- 先对一个任务的重复取平均，再按 scenario 做配对差值和聚类 bootstrap；同时单列学习顺序/运行间方差。不能将几千条 goal 行当作几千个独立样本。
- 仅 2–5 个有效 scenario 时，置信区间不稳定，必须给出原始分组结果，不根据 nominal 样本量强行宣称显著。
- 前期与后期任务难度不同，不以自然流后半程成绩更好直接证明进化。使用固定评估集和固定时刻快照，且不将其反馈输入 K。
- 跨 scenario 迁移不自动等于组合泛化。只有能独立说明“局部机制已出现、整体组合未出现”时，才使用组合泛化表述；否则称跨任务/跨场景迁移。
- 研究者看过 P1 案例不等于这些案例可作为独立发现集之外的证据。P1 材料视为开发数据，正式结论须基于其外的留出分组或官方 test。

## 8. 4090 配置与成本控制

### 8.1 首版资源配置

| 部件 | 配置 | 地位 |
|---|---|---|
| GPU | 1 × RTX 4090 24GB | 设计约束 |
| Actor/归纳/修订 | 现有 Qwen3-8B-AWQ；冻结；顺序复用一个服务 | 旧 Actor 已跑通，新学习循环待验收 |
| 服务 | 继承 C5：32000 context、util 0.45、关闭 prefix caching 等完整配置 | 不在 P1 重开性能调参战线 |
| 输出与原生步数 | actor 3000 输出上限；50 执行块；原配置 100000 任务模型输出总上限 | 原生与辅助推理成本分别记录，辅助调用不得赠送无预算执行 |
| 影子学习 | 每任务最多 2 个事件；每事件最多 12 个新环境分支、6 次模型调用、8000 输出 token | 与原生任务预算分开记账，P1 同样限制单事件推理；本版初始预算 |
| 知识 | 最多 32 活跃规则；检索最多 3 条；注入最多 2048 token | 所有适用对照一致 |
| CPU 重放 | P1 用独立进程串行；P2 后一次性验证并行一致性再启用 | 不共享一个可变 world；并行不等于多 GPU |
| 主机内存/磁盘 | 执行前盘点 CPU 核数、可用 RAM、数据盘与日志增长 | 不根据显存推定主机资源已足够 |
| 4B predictor、优化器、LoRA | 不启动 | 保留旧文件，不占用首版常驻资源 |

上述上下文与截断设定必须通过实际 receipt 确认；不要根据本表猜测原脚本的完整命令。协议中涉及 `--enforce-eager` 等参数时，以已验收脚本为准。[P1][P3]

### 8.2 时间预算使用实测成本模型，不承诺“几天完成”

先分别测量：

```text
每个自然任务 = actor 推理 + 在线辅助推理 + 环境执行
每个学习事件 = 提议/修订推理 + 各分支的初始化/前缀重放/干预/修复/评估
总研究成本 = 所有学习流 + 留出机制比较 + 冻结主评测 + 审计
```

固定程序后，补齐四格执行不需要四条完整 LLM 轨迹；但前缀重放、数据库初始化、checker 和日志仍然耗费 CPU/墙钟，不能按 0 成本计算。

每阶段输出实际累计 token、GPU 忙时/保留时、CPU 重放时间、分支数、峰值显存和磁盘增长。此前报告的“全量 test 约 5–6 天”是旧方法估计，不能复用为本版运行保证。[P1]

### 8.3 先控制实验矩阵，再谈加卡

按 585 个官方 test 任务、5 个最终方法、3 个独立知识/运行配置计算，名义上有 **8775 次完整任务评测**，尚不含学习流。这是组合数量，不是时间估算。

若所有方法对不合格任务确实执行字节级相同的 Actor 输入与流程，可在每个配对运行中共用该任务的 baseline 轨迹，并披露此耦合；资格抽取和各方法真正发生的辅助成本仍单列。只要知识影响基础 Actor 或全局执行行为，该优化立即失效，不能继续借用 baseline 结果。

设实际合格 test 任务数为 E、总任务数为 N、方法数为 M、重复数为 S，则这种严格可复用条件下的任务执行量为：

```text
S × [(N - E) + M × E]
```

E 不按 train 的 12.9% 猜定；只有最终冻结程序在正式阶段自动得到的覆盖统计才有效，不能据此删掉主测试任务。

**主策略：** 局部机制比较先做便宜、完整的对照；只把少量最重要的方法送入全量评测。是否额外借用 H100/H200 只是吞吐选择，不作为方法成立的条件。

## 9. 工程边界与交付接口

### 9.1 复用什么，不重写什么

**复用：** AppWorld 环境/任务/evaluator、官方 ReAct 子类结构、当前 HTTP 模型服务、目标抽取、候选生成和解析、实际代码回写历史、前缀重放、预算与 receipt。

**不重写：** API 实现、数据库语义、官方 task setup、原生 evaluator、基础模型服务。知识来自运行经验；通用 Agent 逻辑不预埋场景专用 API 解法。官方开发规范允许基于训练数据学习，但不应硬编码 API 技巧改变基准含义。[D1]

### 9.2 建议新增的最小模块

以下路径是规划，不表示当前仓库已经存在这些实现。

```text
src/b2_appworld/evo/
  knowledge.py          # 规则 schema、版本与固定检索
  probes.py             # 合法程序/条件提议及联合对照编排
  revise.py             # 用实际证据提出局部知识差分
  validate.py           # 固定验证条件、旧证据回放与提交
  stream.py             # 先评估后学习、快照和预算

configs/evo_v1.yaml
scripts/run_evo_stage.py # 待实现的阶段入口；不能假定已有 CLI 可直接运行
```

不要求为每个概念建一个 Agent 服务。数据库、检索和知识文件优先采用简单 JSON/JSONL 与 CPU 索引，先不引入向量数据库、独立 embedding GPU 或复杂工作流框架。

### 9.3 两个必须严格的接口

**`ReplayReceipt`**：记录环境/任务/前缀/程序/干预/goal 映射的 hash，执行前后目标向量、实际语义差分、可见输出、异常、预算和标签有效性。缓存键包含这些身份，不能只按 task ID 命中。

**`KnowledgeUpdateReceipt`**：记录旧新规则版本、差分、全部支持与反对证据、自动/人工编辑来源、验证结果及更新时间。发布到 `K_{t+1}` 必须发生在任务 t 计分之后。

### 9.4 最小测试清单

1. 相同固定代码前缀重放的一致性；异常前的部分写入不被丢弃。
2. 影子分支隔离，不能写回真实世界；不读取官方 test 学习内容。
3. 条件干预后的观察与环境一致；checker 不适用时产生 unknown。
4. 删除操作的合法性；语法错误不被当作必要性证据。
5. 更新器不能改目标、checker、预算或删除反例；知识版本可回退。
6. `K_t` 在任务内固定；拒绝更新和预算耗尽都能正常结束。
7. 知识载入后真实改变候选生成，而不只改变解释文本。
8. 不合格任务的共享轨迹优化只有在行为确实一致时才启用。

Fixture 只验证实现，不能替代 P1 的真实任务证据。

### 9.5 产物发布

私有实验保存全部证据；公开复现优先提供通用方法代码、锁文件、配置、hash/manifest 和重建脚本。AppWorld 官方要求避免将受保护 bundle 中提取或派生的内容明文散布，知识库、轨迹和标签的发布方式也必须核对其许可与防污染要求。[D1]

本提案不包含任务密钥、训练任务答案或受保护数据库内容；也不要求将此文档自动推送任何远端仓库。

## 10. 风险、停止条件与允许的结论

| 风险 | 最早识别阶段 | 应采取的决定 |
|---|---|---|
| 自然状态中几乎没有成功修复 | P1-A | 区分 Actor 能力与任务可修性；不靠无限候选搜索填满数量 |
| 条件不可观察或不可合法干预 | P1-B | 标未知；不把自然相似实例冒充受控反事实 |
| 每个案例都依赖手写程序/checker/规则 | P1 | 不满足低人工数据目标，停止该环境的扩展 |
| 只有少数同模板机制 | P1/P2 | 官方生成器仅补同机制实例；不能用几千变体冒充广泛迁移 |
| 普通记忆得到同等收益 | P3 | 限定贡献或停止新颖性投入，不继续堆模块 |
| 只增加修复收益，同时严重破坏旧目标 | P3 | 与研究目标冲突，不用单一总分掩盖 |
| 只有学习期反复重做有效 | P3 | 属于额外搜索/重复训练证据，不是冻结迁移能力 |
| `K_probe` 没有额外价值 | P5 | 保留知识级自改进结论，不宣称强元级 RSI |
| 主实验计算超预算 | P3 前 | 先减少非关键比较维度；不得在看过 test 后挑方法或样本 |

**允许论文最后得到有限结论。** 若仅证明可复用的条件知识能降低同域修复错误，就报告同域知识学习；若跨场景证据不足，不改名成组合泛化。若进化过程没有自我改进的独立证据，不把“循环运行”称为学习算法自身的递归提升。

本项目的优先级是：**真实任务中的可学结构 > 可信监督与迁移 > 整洁实现 > 更强 RSI 命名。**

### 11.1 当前只授权的工作范围

这份文档本身不是服务器运行授权。交给执行 Agent 时，第一批任务应只包含 **P0 和 P1**；不启动训练、全量 test、第二环境安装或元级 RSI。

| 次序 | 任务 | 不应顺便做的事 |
|---|---|---|
| 1 | 保存当前工作树与 protocol receipts | 不重置未提交工作，不覆盖旧成果 |
| 2 | 完成目标冻结，固定 Evo 资格与预算 | 不为了覆盖率多次重抽目标 |
| 3 | 索引现有 train 前缀与候选 | 不读取 test、不将 dev 写入 K |
| 4 | 运行一次 P1，按需用唯一预设扩展 | 不反复更换环境、模型、预算直到通过 |
| 5 | 交付 A/B/C 证据与成本，作继续决定 | 不把格式成功、fixture 或计划写成研究结果 |

### 11.2 可直接交给执行 Agent 的提示词

> 项目从旧 RepairScope 四态预测方案转为 RepairScope-Evo：冻结现有 Qwen3-8B-AWQ，通过“操作变化 × 条件变化”的联合执行发现和修订条件化修复知识，暂不训练参数，不实现 K_probe 元级 RSI。
>
> 仅执行本提案 P0/P1。先读取真实工作树、既有协议和 runs 产物，保留已有未提交改动及 C2/C5 配置；完成已有 D1 目标结果的冻结。优先复用原生 train 轨迹和当前前缀重放。不要重新安装环境、重新追求完全确定解码或启动旧 GATE 2 全量采数。
>
> 按固定预算检查 3–5 个真实 train 任务、最多 15 个状态；每个学习事件最多 12 个新影子分支，初批总计最多 180 个。仅允许一次预设扩展：最多再 15 个状态、180 个分支，不得不断采到通过。留出行为重复单列计费。
>
> 需要给出：至少 3 个跨至少 2 个 scenario 的真实成功修复；至少 2 类不同的条件—补偿机制；至少一次系统自动完成的知识修订，并在未参与该次修订的状态中改善行为且未发现旧情形新增损害。所有目标/checker 有效性、程序合法性、条件可比性和失败样本都要记录。无法判断就写 unknown，不允许研究者手写正确规则、任务答案或干预来凑数。
>
> 任务执行先计分，影子学习只影响后续任务。不得使用 dev/test 生成持久知识，不得将反事实分支回写真实环境，不得修改 evaluator 或原始目标。新方法尚无结果；停止与失败结论同样是合格交付。
>
> 完成后输出 P0/P1 报告、所有 witness/probe/update/transfer receipts、覆盖分布和实际开销。不要自动进入 P2/P3/P4，也不要安装第二环境、批量生成新任务或推送受保护实验数据。

### 11.3 本版完成后的预期研究叙事

**问题：** 一次成功修复并没有告诉 Agent 哪些补偿真正必要，错误概括可能反复引入破坏。  
**方法：** 用有限联合反事实执行辨别条件性作用，将执行证据转为可修订的修复知识。  
**学习：** 先做任务，再更新知识；旧知识指导未来修复并接受新反例。  
**验证：** 相同证据与预算下，比较知识质量、负迁移和冻结后的原生任务表现。  
**边界：** 复用现成任务；不凭少数场景增强声称广泛泛化，不凭记忆循环声称元级 RSI。

## 最终决策

**从现成 AppWorld 任务和现有工程开始，只推进 P0/P1。**

P1 若证明真实机制存在且能够自动修订、迁移，再实现最小持续学习器；之后用证据匹配与资源匹配的强对照判断是否进入全量原生评测。需要更多实例时先复用官方 train 生成器，需要更多机制时才审计一个已有第二环境。

**不以人工制造任务、增加模块或不断重做 Gate 来保护一个尚未得到支持的 idea。**
