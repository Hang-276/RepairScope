## 冻结的 idea 与实现语义

以下项目不得自行修改，包括通过“兼容适配”“修 bug”“提效”或消融命名间接改变：

- **Frozen Actor 与 WMA 复用。** Actor 参数冻结；候选生成/聚合、频数去重、Top-k、归一化概率和稳定重排复用 `agent/wma_core.py`，原 WMA 与 RepairScope 共享实现。不得改成额外学习策略、独立 planner 或新一轮 Actor 微调。
- **单一 B-lite。** 一个共享预测器，包含动作条件关系注意力及字段级因果时序注意力；默认 384 维、6 头、4 层关系块、2 层时序块、历史 8 步。不能换成新的多模型方案、EMA teacher 或不同 backbone 来改善主方法结果。既定 backbone 消融只按其脚本运行。
- **Dynamic Scope 与类型化 Patch。** 默认候选上限 256、Scope 预算 128；静态先验、学习作用关系和风险/不确定性扩展保持原义。预测保持/修改/创建/删除、数值及类别/布尔/引用/文本复制；未知项保留 unknown，不能发明无法绑定的实体或字符串。
- **H4 共享参数递推。** 训练中的软递推、明确的梯度边界及正式 H=1/2/4 硬 Patch 指标保持不变。后续预测不能读取真实中间状态或未来返回值，不能悄悄改成 teacher forcing。
- **训练目标。** Step、Rollout、条件 Boundary、Scope Escape，以及 A2 的 paired effect/support 含义、掩码、权重和预热规则保持不变。四态目标标签为 00/01/10/11；部分审计的未知字段不能作为不变或 escape 负例。历史 Scope 的模型版本及标签不能静默重标。
- **控制器。** 预防、目标影响评分、合法只读检查和修复共用同一预测器；保留不修复/noop 候选、保护条件的生效时段及原有决策语义。不能通过少做任务、取消修复、提前终止或放宽目标人为降低损害率。
- **采样。** 风险策略维持 `V(q)=U(q)×D(q)×R(q)/C(q)`，默认 ε=0.1；竞争假设来自同一预测器的 MC dropout。不得替换公式、增设探索模型或删掉随机覆盖。保留完整候选池、选择概率、实际成本和发现结果。
- **信息边界。** Actor、Predictor 和在线检查只接收公开观测、公开任务要求/schema、合法检索及既有历史。隐藏数据库和官方 checker 只用于允许阶段的离线标签或最终评估，不得成为在线输入。dev/查询/测试结果不得进入训练或回放。
- **真实分支与预算。** 分支仅在训练侧使用，来自可验证的相同前缀。条件通过真实合法 API 操作构造，并由合法只读查询确认；不能仅编辑输入 token。两分支或四格均实际执行，前缀重放、条件、检索/查询、失败调用和续跑完整计费。成本无法核实时停止，不能把失败当免费样本。
- **指标和划分。** 维持官方划分及源任务/条件变体/兄弟分支的组隔离。TGC/SGC 只依据原生 tracker 和完整计划集，SGC 按原生 scenario 严格聚合；不以子检查 pass rate 替代。保持 Recall@B、escape、Brier/ECE、四态 F1、typed Patch、目标退化/修复损害、成本和组 bootstrap 的定义。

首轮训练配置、优化器、有效 batch、30 epochs、BF16、三个种子及固定预算以 proposal 和已提交配置为准，不做效果驱动的调参。显存问题只可采用 proposal 已允许的工程调整，例如减 micro-batch、相应增加累积，保持有效 batch、反事实兄弟组完整性和各方法公平性；无法同时保持时停止并按机制/公平性问题报告。

## 哪些问题可以自主修，哪些必须停止

可以自主修复环境路径、依赖/驱动安装、模型服务连通、文件权限、公开 API 的参数/返回结构兼容，以及能够证明不改变上述任何语义的工程 bug。每次只做定位该故障所需的最小回归，并按下文记录仓库外日志。若修复影响已完成结果，保留旧结果和成本，明确标记版本边界；需要同版本对照时不能只重跑有利的方法。

**发现机制 bug，或拟议修复会改变架构、损失/梯度含义、采样、标签、目标、指标、划分、控制决策或实验公平性时，立即停止受影响实验。不得先写补丁再请求批准。** 不得用改配置、删异常样本、忽略失败、扩大某一方法预算、放宽目标、替换基线或改指标绕过问题。即使你认为修复方向显然正确，也必须先报告，等待用户明确审批。无法确定是否属于机制问题时，按机制问题处理。

机制问题的最小复现使用已有失败收据或只读分析；不要继续消耗受影响实验的 GPU/API 预算来“看看改后效果”。可以继续与问题无关的证据整理，但不得继续产出依赖错误机制的正式结果。

## 必须放在仓库外的工作日志

在首次修复前建立仓库外日志。默认目录为 `repo.resolve().parent / "RepairScope-server-notes"`。先解析真实路径，确认目录和日志文件经符号链接解析后都位于仓库外；不能仅凭字符串前缀或 `.gitignore` 判断。

可用以下方式准备路径；这一步不把日志写入仓库：

```bash
export REPAIRSCOPE_REPO_ROOT="$(git rev-parse --show-toplevel)"
export REPAIRSCOPE_NOTES_DIR="$(dirname "$REPAIRSCOPE_REPO_ROOT")/RepairScope-server-notes"
python - <<'PY'
import os
from pathlib import Path
repo = Path(os.environ['REPAIRSCOPE_REPO_ROOT']).resolve()
notes = Path(os.environ['REPAIRSCOPE_NOTES_DIR']).resolve()
paths = [notes, (notes / 'BUGFIX_LOG.md').resolve(),
         (notes / 'MECHANISM_ISSUES.md').resolve()]
for path in paths:
    if path == repo or repo in path.parents:
        raise SystemExit(f'拒绝把工作日志放进仓库: {path}')
notes.mkdir(parents=True, exist_ok=True)
for path in paths[1:]:
    print(path)
PY
```

每次工程修复追加到上述绝对路径的 `BUGFIX_LOG.md`，至少记录：

```text
时间、服务器/设备与实际 repo 绝对路径：
起始 HEAD、分支、工作区已有改动：
任务/方法/种子、配置/数据/checkpoint 标识：
问题与原始报错、修复前证据绝对路径：
为何属于不改变研究语义的工程问题：
修改文件、变更说明：
仓库外 patch 绝对路径、diff SHA-256：
修复 commit（如已本地提交；否则写未提交）：
执行命令（脱敏）、修复后必要最小回归及证据：
已消耗的调用/分支/GPU 时间与失败预算，受影响结果：
后续从何处继续、是否存在未解决边界：
```

保留修复前后 diff；只保存本次相关且已检查不含凭据的 patch，并计算 hash。修复 commit 和 diff hash 对应实际代码，不得用之后的改动冒充已验证版本。若未创建 commit，明确记录未提交及当时 diff hash，不能编造 commit。

机制问题写入同目录的 `MECHANISM_ISSUES.md`：包含问题事实、复现命令/证据、当前与期望语义、拟议修复、可能影响的机制/结果/公平性、已消耗预算、已停止的实验，以及需要用户决定的具体事项。报告该文件的**实际绝对路径**后等待用户审批，不要擅自实施拟议修复。

日志、patch、凭据不得 `git add` 或复制回仓库。保持已有源码、数据和失败证据可追溯；未经额外用户授权不自动 push/merge、强制重置或覆盖远端。本次代码交付的发布授权不等于服务器后续修复的持续发布授权。

## 真实环境、公开映射与运行顺序

按 `SERVER_RUNBOOK.md` 安装必要服务器依赖和 AppWorld 数据，配置冻结 Actor 服务、GPU、数据根目录及公开观测/目标映射。密钥通过环境变量或用户已有安全配置读取，不写入源码、日志、命令输出或 Git。

实际公开映射尚需服务器数据对齐。只能依据真实公开 API 文档、返回 schema 和公开任务要求，把字段类型、单位、引用、未知性及目标谓词等义映射到已有 schema。保留公开来源和确定性转换的证据。不得从隐藏数据库/checker 反推在线要求，不得把示例配送/支付任务伪装成 AppWorld 真实任务，不得为了跑通而简化任务目标。字段或目标含义不清、需要新机制才能表达时停止相关链路，写明缺失信息并询问用户。

确认运行输入和服务就绪后，按以下固定顺序推进，不在其间插入算法筛选实验：

1. 一次必要的真实接入 smoke，仅验证此前未在服务器跑过的接口/设备链路；已经验证的 CPU fixture 不重复训练。
2. 一次采集并冻结真实自然轨迹和合法训练分支，构建主 A 共享训练集。保留官方源任务划分、前缀动作/输出/指纹、审计域、真实成本、数据 hash 和版本。单独保存 dev 普通冻结轨迹。
3. 主 A：`bash scripts/repairscope/run_main_a.sh`。A0 为 Frozen Actor；A1 为 Step+Rollout 普通预测器；A2 增加 paired effect/support；A3 为完整 RepairScope；A4 去 Boundary；A5 去 Escape 并使用既定不确定性调度。A1–A5 共用全部自然/反事实数据、容量与训练计划，各运行三个固定种子。统一 Actor/提示/候选缓存、候选数、控制器和检查/修复预算，不给完整方法额外数据或资源。
4. 通过 `EVAL_DATA` 接入同一次主结果的 H=1/2/4 预测指标；仅用有效 dev H1 审计记录选择一次阈值。校准收据绑定 checkpoint hash 和风险来源。正式任务只读取冻结阈值，禁止测试调参、测试期更新或回滚分支搜索。
5. 主 B：`bash scripts/repairscope/run_main_b.sh`。随机、不确定性、新颖性/可学习性、风险四策略使用对应种子**同一 A3 起点**、同一合法候选池、损失与执行预算。保持 `TRAIN_DATA` 以初始化同一旧数据回放；使用 `CHECKPOINT` 自定义起点时同时核对对应 `CALIBRATION_FILE`。A3 dev 阈值在持续更新中冻结，保留初始来源，不在查询任务上重新拟合。
6. 按预定累计预算记录冻结查询的目标损害、预测与成本曲线。初始查询提供共同基线；查询与采样/更新按任务族隔离，结果不回流。训练执行成本和查询成本分别列出，Actor/预测器调用及前向时延另列。预算不足以再执行一个完整实验时保留实际已耗成本，不能假称花满或忽略尾部成本。
7. 完成既定各消融：`bash scripts/repairscope/run_all_ablations.sh`，以及单独的 `bash scripts/repairscope/ablate_no_probing.sh`。不探索方案从相同 A3 起点、相同冻结查询出发，零探索预算，输出目录独立。各脚本的定义保持不变，不按结果临时删减或增加机制。
8. 依照原生指标和预定分组汇总全部结果、三个种子、组 bootstrap、绝对提升及成本；列出失败、缺失和实际覆盖。没有稳定提点时，如实根据主对照和消融分析，不修改 idea、不追加一串小验证试验。

具体命令及 `CONFIG`、`APPWORLD_ROOT`、`TRAIN_DATA`、`EVAL_DATA`、`PROBE_PLANS`、`RUN_ROOT`、`SEEDS` 的设置按 runbook 执行，不直接复制未替换的示例路径。选择全新且独立的结果根目录；代码已使用唯一原生 experiment namespace 并拒绝覆盖已存在的运行收据，不要删除 guard 或清空旧结果来继续。只有完全相同数据/config 的训练可按已有 `--resume` 机制精确续训；不把另起训练写成续训。
