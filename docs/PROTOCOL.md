# RepairScope-Evo P0/P1 协议

研究依据为 [Phased Proposal v1.0](PROPOSAL_v1.0.md)。提案中的历史服务器报告属于报告来源，不能替代本次服务器核验。用户后续明确废弃旧工作，因此旧代码已由新方案替换；[迁移记录](MIGRATION.md) 说明这一覆盖关系。

## 范围与推进条件

当前只实现 P0/P1，不自动进入 P2，不启动参数训练、全量 test、第二环境安装或场景生成。P1 不是论文结果，阶段通过也不代表统计显著或广泛泛化。

P0 冻结资产、数据边界、D1 目标、任务顺序、预算与重放证据。P1 验证真实自然状态中是否存在可自动发现、修订并迁移的条件化修复机制。P1 的 A、B、C 三项均有真实证据后，才能讨论 P2 实现。

## 数据与可见性

持久知识、实验选择与修订仅能使用 train。dev/test 内容和官方参考解不能进入学习模型上下文；隐藏 checker 真值不能进入在线修复生成上下文，也不能用于在线触发或选择修复。train 离线执行标签可以用于机制学习和审计。test 在 P4 前不展开；P0 可以核验既有 split manifest 的身份和统计元数据。旧 8k/16k 或不同服务配置的轨迹只能作为带来源标记的诊断资产，不能混入主协议学习流。

`EvoEligibility-v1` 在看到新方法结果前固定：任务须具有至少两个独立、持久、可操作的状态目标或明确保留约束，同时保留所有其他原任务要求。学习事件至少有一个待恢复目标和一个执行前已满足的保护目标。离线真值用于研究资格与评分，不决定在线触发或候选选择。优先复用已有 D1 抽取，不逐任务重抽直到覆盖满意。

来源标签必须保留：`natural_regression`、`natural_failure`、`natural_incomplete`、`cf_intervention`、`official_generator`、`synthetic_fixture`。原生自然事件与人工夹具不能合并；反事实副本不是新的独立场景。当前 P0/P1 入口不自动运行官方 generator。

## P0 交付与通过条件

P0 读取操作者明确提供的资产说明，核验文件身份和 hash，冻结协议及 train 数据边界。核心产物为：

```text
assets.json
protocol.yaml
protocol_migration.md
data_manifest.json
goals.lock.json
P0_report.md
```

`protocol.yaml` 使用 JSON 子集语法，因此可由标准库读取并且仍是合法 YAML。运行目录中的 `protocol_migration.md` 记录阶段迁移；完整仓库级迁移说明见 [MIGRATION.md](MIGRATION.md)。产物仅写入操作者指定的运行目录。

通过要求：完整版本及数据身份确定；目标冻结；学习资产属于 train 且不暴露 dev/test；至少一个既有前缀有可信重放证据。重放须覆盖 Python 执行上下文和异常前的部分写入。若接口未改且有可信 receipt，可以引用已有证据；引用不等于本地重新执行了该实验。资产缺失、不一致或不可核验应报告 `blocked`，不能靠空文件、占位 hash 或声明式 `ready` 通过。

## P1 固定预算

| 项目 | 上限或要求 |
|---|---|
| 首批原生 train 任务 | 3–5 个，按冻结 scenario 轮转次序 |
| 首批不同自然状态 | 10–15 个；最多 15 个 |
| 每状态初始候选 | 最多 4 个；接收 1–4 个实际已有候选，不补造缺失候选；失败与 unknown 同样计入分母 |
| 每事件新影子分支 | 12 个，含候选核验、四格探测和更新回归检查 |
| 首批总新影子分支 | 180 个；缓存命中单列 |
| 每任务实际知识学习事件 | 最多 2 个；额外状态保留全部候选见证尝试，不再启动联合学习 |
| 每事件学习侧模型调用 | 最多 6 次 |
| 每事件学习侧输出 token | 合计最多 8000 |
| 留出行为评估 | 最多 3 个案例，每案例最多 3 次新旧知识配对，共最多 18 次运行 |
| 预设覆盖扩展 | 仅一次；额外最多 15 状态、180 新分支 |
| 主机制实验人工编辑 | `human_task_edits = human_rule_edits = human_intervention_edits = 0` |

扩展只能从尚未检查的原生 train 合格任务中选择，至多完成冻结资格清单的一轮。不能通过换种子、循环覆盖同批任务或另起输出目录重置科研总预算；服务器操作者须保存阶段总账。超限或证据不足记录 unresolved 和停止建议，不能自动放宽预算。

15 状态是每阶段的自然状态上限，与每任务两次实际知识学习事件分别计数。当前实现记录完整分支身份及 `cache_key`，但没有重放缓存；所有实际分支均计费，缓存命中数为 0。缓存复用仍属于后续工作，不能在成本中预扣。

## 执行、机制与更新

先记录原任务成绩；同一任务内 `K_t` 固定。影子实验只能影响后续任务或独立知识评估，不能替换原任务成绩。所有分支须从隔离副本重放；失败发生前的真实部分写入应保留。固定代码重放与重新生成行为分别记录。

每事件最多三个竞争解释。系统自动提出基础修复 `r0` 与含补偿的 `r1`，以及可观察条件 `c0/c1`。必须执行四格 `(c0,r0)`、`(c0,r1)`、`(c1,r0)`、`(c1,r1)`；补偿位置和执行顺序属于程序含义，不能默认只在末尾追加。

程序变化必须合法。语法损坏、变量未定义、非法参数、截断不算语义必要性证据。条件变化只能通过隔离副本中的合法 API，记录附带写入与可见观察。对照须保留同一任务语义、恢复承诺与执行前保护目标真值；若改变了任务要求中对象集合，应拒绝纯背景对照解释。多个因素一起改变时，只能归因于该组合。

影子机制标签必须由经审计、在两个条件状态中语义一致的目标谓词判断。原生 evaluator 可能依赖初始状态，不能直接用于任意干预世界。checker 不适用或对照不可比时输出 `unknown`，不得当成负例或删去以提高成功率；原任务最终成绩仍使用原 evaluator。

知识更新仅允许新增、条件收窄/扩展、补偿增删、局部分支拆分及弃用。拟议规则必须实际适用于当前可见条件，且注入该规则后重新生成的程序须通过执行检查。相关旧证据既重放旧固定程序，也在旧可见上下文中用新知识重新生成并执行修复；两类检查的所有分支、模型调用和输出 token 均计入同一事件预算，不为扩大旧证据档案漏查或赠送计算。更新须修复至少一项已观察知识错误或补足能力，相关旧证据未发现新增损害。更新器不能改目标、checker、预算、划分或删除历史反例。预算不足保留候选版本，不强制提交。`validated` 只表示满足指定证据条件。

当前实现的更新回归范围为已接受的自然见证前缀，包含固定代码和新知识重新生成两种检查。历史条件变体未被穷举回放，报告会保留该限制；完整反事实记录不能因为未重跑而被删除。阶段继续建议需要审查这项覆盖，不能解释为全部旧条件已验证无退化。

## P1 A/B/C 验收

- **A：真实成功见证。** 至少 3 个有效修复，覆盖至少 2 个 scenario；每个修复恢复预先声明的全部 `G_fix` 并保持可判断的 `G_keep`。读取无关信息、普通任务推进不能冒充修复。
- **B：条件性机制。** 至少 2 类不同条件—补偿机制，具备合法、可比较的四格固定程序执行、完整目标向量及实际状态差分。同模板换实体不算第二类机制。
- **C：自动演化及迁移。** 系统形成 `K0 → K1 → K2`，至少一次实质修订改变后续生成行为，并在未参与该次归纳、实验选择或回归门控的状态中改善恢复或减少损害；相关旧情形未发现新增退化。报告所有配对重复，不能凭单次较好输出宣称稳定改进。

迁移报告须证明变更规则确实注入新知识提示、新旧知识提示 hash 不同、实际程序行为改变且执行来源为真实 AppWorld；不能将模型自身输出波动计为知识带来的改善。所有新旧配对及拒绝、失败均存档，留出结果不控制提交。

修订反例可以进入学习池，但不能同时成为这次修订的独立迁移证据。留出状态若评估后再用于学习，必须记录分区转移时间，停止作为该修订的独立证据。

P1 应输出 `P1_report.md`、`witnesses.jsonl`、`joint_probes.jsonl`、`knowledge_versions.jsonl`、`transfer_cases.jsonl` 和 `coverage_and_cost.json`。包含成功、失败、unknown、拒绝、无更新及所有实际成本，不只导出正例。报告至少覆盖 task/scenario/mechanism、人工编辑与审计时间、模型 token、分支及缓存、CPU/墙钟、可获得的 GPU 指标和磁盘增长。没有测得的指标写 unavailable，不能估作实测。

## 允许的结论

本地测试通过表示代码在测试输入上工作。合成夹具表示编排路径被检查。完整 receipts 表示证据身份可追踪；它们不自动证明输入真实、checker 正确、因果成立或方法有统计优势。P1 证据属于开发资料，正式迁移结论须另有留出分组或冻结原生评测。SGC 指 Scenario Goal Completion，不能写成子目标完成率。
